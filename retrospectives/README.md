# Retrospectives

One file per retrospective, named for the date it was held. These are about
**how the work was done** — the loop, the instruments, the division of labour
between a person and an agent — rather than about what the code decided. A
decision that shaped this codebase belongs in `adr/`; what a file format taught
belongs in `LEARNINGS.md`; what was done and when belongs in `PROGRESS.md`.

They are written to be read from **another project**. The evidence in them is
necessarily from this one — an office suite matched against Word — but the
findings are meant to survive the change of subject, so each states its lesson
in terms that do not depend on documents, layout, or Rust.

Like the records in `adr/`, a retrospective is not rewritten once held. A later
retrospective that revises an earlier finding says so and points back.
